# Контент-файлы CashPet — описание

> **Черновик формата от Ярика.** Окончательный формат JSON утверждён в [контрактах](08-контракты.md), раздел 7; `tasks.json` — [07-формат-заданий](07-формат-заданий.md).

## Новый формат — что читает загрузчик

**Образцы всех файлов** — `content/src/test/resources/samples/`: их читает тест `ContentLoaderTest`, значит, они точно подходят. Переносишь файл в `content/src/main/resources/content/` — начинай с образца и меняй значения, ключи оставляй как есть.

| Файл | Корень | Запись |
| --- | --- | --- |
| `tasks.json` | `{ "tasks": [...] }` | Задание по 07 |
| `shop.json` | `{ "items": [...], "task_items": [...] }` | `{ id, name, part: "need"/"want", price, effects: { satiety, care, mood }, accessory }`. `task_items` — вещи только из текстов заданий, на витрину не идут |
| `goals.json` | `{ "catalog": [...] }` | `{ id, name, cost }` |
| `jobs.json` | `{ "jobs": [...] }` | `{ id, title, reward }` |
| `economy.json` | сразу поля | Все числа экономики, см. образец |
| `pet.json` | `{ "breeds": [...], "colors": [...] }` | `{ id, name }` |
| `texts.json` | `{ "feedback_reasons": {...}, "pet_reasons": { "week": {...}, "now": {...} } }` | Ключ — причина строчными (`bought_need`, `hungry`), значение — фраза |
| `neighbors.json` | `{ "characters": { "toroplivy": {...}, … } }` | `{ name, role, plan_tips: [...] }`, ключ — `id` для `neighbor_lines` в заданиях. `plan_tips` — советы на экране «План», у Торопливого и Осторожного поровну. Старые `lines` и `strangers` загрузчик пропускает |
| `onboarding.json` | `{ "screens": [...] }` | `{ id, kind: info/player_name/look/pet_name/difficulty, text, bullets, fine_print, input, choices, button, pet_reply, skippable, next }` — по порядку показа |
| `glossary.json` | `{ "terms": [...] }` | `{ id, term, definition }` |

Ключи и значения-перечисления — строчными: `"need"`, `"easy"`, `"satiety"`, `"good"`. Лишние ключи (`_meta`, `note`) загрузчик пропускает. Ошибку в файле тест покажет с его именем: `shop.json: …`.

Ниже — описание черновика Ярика, по которому собраны нынешние файлы.

Шесть JSON-файлов с игровым контентом, собранные по итоговой дорожной карте. Лежат в модуле `content` и загружаются им; числа экономики — в [02-экономика](02-экономика.md).

Общие плейсхолдеры во всех файлах: `{petName}` — имя питомца, задаётся игроком в онбординге; `{needMin}` — стоимость обязательных покупок за неделю: пока постоянна, 50 (корм 30 + шампунь 20); рост со стадией — после 29.09.

Во всех файлах есть служебный ключ `_meta` (заметки, не игровые данные) — из конфига в проде его можно не грузить в клиент.

## tasks.json

Все 26 заданий модулей 0-8.

**Поля задания:** `id`, `module`, `title`, `topic` (темы для отчётности по ТЗ), `difficulty` (`easy`/`medium`/`hard`), `star` (входит в обязательный минимум ТЗ), `mvp` (нужно к 29.09 или расширение), `reward: {coins, base_xp}`, `steps[]`.

**Шаг** (`steps[]`) содержит `situation`, варианты `options[]` (`id`, `label`, `consequence`, `feedback`, `k`) либо специфичные под шаблон поля (`items`, `outcomes`, `flags` — для заданий с корзинами/чек-листами/итогами по условию).

**Многошаговая оценка.** Там, где k зависит от сочетания ответов на нескольких шагах (2.2, 2.3, 3.2, 4.3, 5.1, 7.4, 8.2), у задания есть отдельный блок `scoring` с таблицей комбинаций — k не размазан по отдельным `options`.

**Награда.** `reward.coins` — фиксированная сумма (не зависит от k). Итоговый XP = `round(reward.base_xp × k)`. Формула повторного прохождения — в `tasks._meta.reward_repeat_formula`.

**Особые пометки:** `blocked: true` — выбор не засчитывается, ведёт в отдельный диалог; `faceless: true` — у персонажа нет постоянного облика (модуль 7); `random_outcome: true` — исход разыгрывается (только 7.6); `neighbor_lines[]` — реплики соседей, привязанные к заданию.

## shop.json

Каталог магазина: `need[]` (нужное), `want[]` (желаемое), `gifts.items[]` (подарки, доступны только во время события).

**Поля товара:** `id`, `name`, `price`, `satiety`/`comfort`/`mood` (эффект на показатели питомца, `null`/`0` — не задан), `note`.

Открытый вопрос зафиксирован в `_meta.notes`: растут ли цены каталога вместе со стадией питомца, или на старших стадиях нужны другие/более сильные позиции — решение ещё не принято.

---

## goals.json

`catalog[]` — три реальные цели копилки (Когтеточка/Домик/Велосипед), с ценой; сроки накопления — в [02-экономика](02-экономика.md).

`task_specific_flavor_goals[]` — отдельно вынесенные цели, которые встречаются только внутри текста конкретных заданий (3.1, 3.2) и **не совпадают** с `catalog` — это осознанное решение (разнообразие), не ошибка.

---

## glossary.json

Плоский список терминов: `id`, `term`, `definition`, `module` (в каком модуле термин впервые вводится), `mvp` (термины модулей 6-8 помечены `false`).

---

## onboarding.json

`screens[]` — семь экранов знакомства (1-7) по порядку показа, с текстом, кнопками, полями ввода и валидацией (экран 4 — имя питомца).

`optional_not_implemented` — экран выбора сложности между 6 и 7, отложен.

`starting_balances` — стартовые 20 монет и 10 XP (это единственная стартовая сумма, без отдельных 100 монет дохода первого периода поверх неё).

---

## neighbors.json

`characters` — четыре постоянных соседа (Торопливый, Осторожный, Рыжехвостик, Длинноус), у каждого список `lines[]` с привязкой к заданию (`task`) и контекстом.

`plan_screen_mechanic` — как реплики соседей используются на экране «План» (тап по аватару).

`strangers` — отдельно незнакомцы модуля 7: принцип безликости и явное исключение для 7.6 (единственное задание, где используется облик знакомого соседа, потому что тема — подделка личности, а не незнакомец).

`_meta.known_cast` — фиксированный список из 4 имён, чтобы новые персонажи не появлялись по ходу реализации без решения команды.
