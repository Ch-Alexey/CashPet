## 🔌 Подключение экранов

ViewModel лежат в `main` с 25.09 (PR #25–#29). Если в твоей ветке их нет — ветка создана раньше: `git pull origin main`.

Экран получает ViewModel через `viewModel(factory = …)`, читает `uiState` через `collectAsStateWithLifecycle()` и вызывает методы на кнопках. Считать, сохранять и подставлять тексты экрану не нужно — всё уже в `UiState`. Библиотеки (`lifecycle-viewmodel-compose`, `lifecycle-runtime-compose`, `navigation-compose`) в `app` подключены.

| Экран | ViewModel — как создать | Кнопки → методы | Куда вести |
| --- | --- | --- | --- |
| Старт | `StartViewModel.Factory` | — | `loading` — «Играть» неактивна; «Играть»: `hasProfile` → Дом, иначе онбординг в слоте `if (demo) Slot.DEMO else Slot.CHILD` |
| Онбординг | `OnboardingViewModel.factory(slot)` | `onNameChange`, `onLookChange`, `onDifficultyChoose`, `next`, `skip`, `back` | `finished` → задание `firstTaskId`, после него — Дом |
| Дом | `HomeViewModel.Factory` | `closeWeek()` — после диалога по `closeWarning` | `uiState == null` → онбординг; `weekClosed` → Итог недели и сразу `onWeekSummaryOpened()` |
| План | `PlanViewModel.Factory` | `increase(Part)`, `decrease(Part)`, `confirm()` — после диалога «Потом план не изменить» | — |
| Магазин | `ShopViewModel.Factory` | `buy`, `addToWishlist`, `removeFromWishlist`, `buyWithSavings` (вариант «взять из копилки»), `onMessageShown` | `rejection == PlanNotConfirmed` → «Сначала план» ведёт на План |
| Копилка | `SavingsViewModel.Factory` | `chooseGoal`, `deposit(5 / 10 / 20)`, `previewWithdraw(n)` → окно «было → станет», `withdraw`, `buyGoal`, `onMessageShown` | до плана «Пополнить» → План |
| Задания | `TasksViewModel.Factory` | `doJob()` — «Помочь по дому», `onMessageShown` | карточка → задание `taskId` |
| Задание | `TaskPlayViewModel.factory(taskId)` | `choose`, `onFollowup(кнопка)` — диалог заглушки, `retry` — «Попробовать иначе», `next` — «Дальше» | `finished` → панель `feedback` с наградой, потом назад |
| Итог недели | `WeekSummaryViewModel.Factory` | — | «Следующая неделя» → План |
| Демо (плашка на Доме, кнопка в разделе взрослого) | `DemoViewModel.Factory` | `start`, `speedUp` — «Ускорить», `reset`, `exit`; итоги прогона `weeks` показать по очереди → `onWeeksShown` | `navigate`: `HOME` / `ONBOARDING` (в демо) / `START`, после перехода — `onNavigated()` |
| Настройки | `SettingsViewModel.Factory` | `setSound`, `setAnimations` | «Для взрослых» → барьер |
| Барьер | `viewModel<AdultGateViewModel>()` — без фабрики | `onInputChange`, `submit` | `passed` → раздел взрослого |

**Три правила для всех экранов:**

- `uiState == null` — профиля нет (или задания нет): не показывать пустой экран, а вести в онбординг (или назад к списку).
- `feedback` — показать общую панель «что изменилось», `rejection` — объяснить причину отказа; по «Понятно» — `onMessageShown()`.
- События «один раз» (`weekClosed`, `navigate`, `finished`) — перейти и сразу сообщить ViewModel, что обработано, иначе переход повторится после поворота экрана.

**Пример — Дом и Старт.** Сам экран остаётся тем же, что на `PreviewSamples.home`: он принимает `HomeUiState` и лямбды. Обёртка `…Route` только связывает его с ViewModel и навигацией.

```kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.LaunchedEffect
import androidx.compose.runtime.getValue
import androidx.lifecycle.compose.collectAsStateWithLifecycle
import androidx.lifecycle.viewmodel.compose.viewModel
import io.github.chalexey.cashpet.app.vm.HomeViewModel
import io.github.chalexey.cashpet.app.vm.StartViewModel
import io.github.chalexey.cashpet.core.model.Slot

@Composable
fun StartRoute(onHome: () -> Unit, onOnboarding: (Slot) -> Unit, onAdult: () -> Unit) {
    val vm: StartViewModel = viewModel(factory = StartViewModel.Factory)
    val state by vm.uiState.collectAsStateWithLifecycle()
    StartScreen(
        playEnabled = !state.loading,
        onPlay = { if (state.hasProfile) onHome() else onOnboarding(if (state.demo) Slot.DEMO else Slot.CHILD) },
        onAdult = onAdult,
    )
}

@Composable
fun HomeRoute(onWeekSummary: () -> Unit, onNoProfile: () -> Unit) {
    val vm: HomeViewModel = viewModel(factory = HomeViewModel.Factory)
    val state by vm.uiState.collectAsStateWithLifecycle()
    val home = state
    if (home == null) {
        LaunchedEffect(Unit) { onNoProfile() }
        return
    }
    LaunchedEffect(home.weekClosed) {
        if (home.weekClosed) {
            vm.onWeekSummaryOpened()
            onWeekSummary()
        }
    }
    HomeScreen(state = home, onCloseWeek = vm::closeWeek)
}
```

`StartScreen` и `HomeScreen` — твои экраны, имена и параметры любые. Остальные экраны подключаются так же — по таблице выше.

## ✅ Можно сейчас

0. **`git pull origin main` и подключить экраны к ViewModel** — по разделу «🔌 Подключение экранов». Заглушку с `PreviewSamples.home` в навигации убрать. Ветку с экранами стоит сразу опубликовать (`git push`), даже черновиком: конфликты с `main` всплывут раньше.

1. **Открыть проект** в Android Studio: File → Open → папка `CashPet`, Run ▶ на телефоне. Должен открыться экран «CashPet · Заданий в контенте: 7».
2. **Написать в чат статус графики:** что готово из пробы «один кот × 3 стадии по частям». От этого зависит, успеваем ли кота 3 × 3 к 29.09.
3. **Экраны прямо в `app`** — ветка `sanya/screens`, пакет — `io.github.chalexey.cashpet.ui` или `...app.ui`, как в контрактах, **выбери с Виталиком, пока нет ни одного экрана**: тема, нижнее меню, верхняя панель, затем Дом, План, Магазин, Копилка, Задание, Итог недели. Данные — классы `UiState` из `app/src/main/kotlin/.../app/vm/UiState.kt` (по разделу 8 [контрактов](../08-контракты.md)). **Свои `data class` для состояний не объявляй** — бери эти; для `@Preview` — готовые примеры `PreviewSamples.home`, `.plan`, `.shop` и т. д., для настоящей игры — ViewModel из таблицы выше.
4. **Общая панель обратной связи** («Баланс 115 → 90…») — один компонент на все действия, `FeedbackUi`.
5. **До плана** в Магазине вместо «Купить» — кнопка «Сначала план», в Копилке «Пополнить» ведёт на план (`planConfirmed` в `UiState`). Тупиков быть не должно.
6. **Тема:** цвета, шрифт Nunito (OFL), кнопки от 48 dp, текст от 16 sp, цвет никогда не единственный носитель смысла.
