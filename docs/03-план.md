## Архитектура одним взглядом

```
app/      Android: Compose-экраны, навигация, ViewModel, анимации     ← Саня (экраны), Виталик (ViewModel)
data/     Android: Room, сохранение профиля и истории                  ← Виталик
content/  Kotlin: JSON-контент + загрузчик + проверки                  ← Ярик (JSON), Виталик (код)
core/     Kotlin без Android: модели, экономика, период, рост,         ← Леха
          состояние кота, симулятор сценариев
```

Зависимости только сверху вниз: `app → data, content, core`; `data → core`; `content → core`. `core` не знает об Android, поэтому его тесты идут за секунды.

**Стек:** Kotlin, Jetpack Compose (Material 3), Navigation Compose, ViewModel + StateFlow, корутины, Room (KSP), kotlinx.serialization, внедрение зависимостей вручную (один `AppContainer`, без Hilt — меньше магии для новичков), JUnit 5 в `core` и `content`, GitHub Actions. minSdk 26 (Android 8.0), compile/target — последний стабильный, который предложит Android Studio. Разрешений Android нет ни одного, даже интернета.

## Тесты

Требование ТЗ (п. 3.4, ответы заказчика, критерий 8.2): логика бюджета, списаний, накоплений и прогресса покрыта автотестами, и расчёты совпадают с нашими описанными правилами. Поэтому каждое правило из [экономики](02-экономика.md) пишется вместе с тестом, а не в конце.

**Леха (`core`):**

- Баланс никогда не уходит в минус.
- Покупка при нехватке отклоняется с объяснением, чего не хватает.
- Сумма плана не превышает доступное, остаток считается верно.
- Перенос в «Хочу потом» не меняет баланс и факт.
- Снятие из копилки уменьшает сумму и срок ровно так, как показано до подтверждения.
- Заработок внутри периода не входит в план, остаток переходит в следующий период.
- Очки роста и стадии на трёх сценариях совпадают с таблицами [экономики](02-экономика.md).
- Стадия не понижается, очки не сгорают.

**Виталик (`data`, `content`, демо):**

- Профиль, баланс, покупки, копилка, цель, прогресс восстанавливаются после перезапуска.
- Весь контент загружается; у задания 2–3 варианта, у каждого объяснение и награда > 0; суммы кратны 5 и не выходят за 999; каждая тема покрыта.
- Тест-сторож баланса: неравенства раздела 19 и три сценария на 5 периодов.
- «Ускорить» даёт те же результаты, что ручной прогон тех же решений; сброс демо возвращает исходное состояние.

## Процесс в Git

- `main` защищена: только через PR, CI зелёный, одно одобрение.
- Ветка на задачу: `имя/что-делаем`, например `sanya/plan-screen`.
- CODEOWNERS: `core/` — Леха; `data/`, код `content/` — Виталик; `app/` — Саня и Виталик; JSON-контент — одобряет Леха или Виталик.
- CI на каждый PR: сборка, все тесты, проверка контента, APK как артефакт.
- Новичкам в Git удобнее GitHub Desktop.

## Как Ярик работает с контентом и балансом

- Меняет только файлы в `content/src/main/resources/content/` и таблицу баланса. Код не трогает.
- Каждая правка — отдельный PR. Если тесты-сторожа красные, в логе CI написано, какое правило нарушено; исправляет и пушит снова.
- Баланс: меняет числа в JSON → запускает `gradlew :core:simulate` (на Windows без `./`) → смотрит таблицу трёх сценариев. До появления симулятора — `python tools\econ_sim.py`.
- DeepSeek — для черновиков. Каждый текст сверяется с требованиями к языку (раздел 20 рамок): предложения до 12 слов, числа кратны 5, без стыда и восклицаний в неудачном исходе, термин — с пояснением.
- Все тексты игры ведёт он один — единый тон.

## Графика: требования

Схема: **ИИ-эскиз → ручная векторная обводка по частям → анимация в Compose.** Бесплатные ассеты — для значков и фонов, по ходу.

**Эскизы (Саня):**

- Сервис генерации фиксируем один, выбирает Саня до 19.09 (ChatGPT, Kandinsky, Шедеврум или другой). Перед началом — прочитать условия использования: разрешено ли использовать и распространять результат.
- Каждую генерацию записываем в `design/ai-log.md`: дата, сервис и модель, запрос, что получилось, ссылка на условия использования и дата их проверки. Это требование ТЗ для ИИ-графики.
- В запросах **не называем существующих персонажей и не загружаем чужие картинки как образец**: «как Том и Джерри» — только описание стиля словами (мультяшный, антропоморфный, прямоходящий), иначе получится производная от защищённого персонажа.
- Нужно: 3 кота с разным силуэтом (например, пушистый, гладкошёрстный, вислоухий) × 3 стадии (малыш, подросток, взрослый), вид анфас, нейтральная поза, плоский мультяшный стиль.

**Векторизация (Саня):**

- Figma или Inkscape, экспорт SVG → импорт в Android Studio как Vector Drawable.
- Кот делится на части-слои: тело, голова, глаза открытые и закрытые, рот (улыбка, нейтральный, грустный), уши, руки, ноги, хвост.
- Общее поле 512 × 512 для всех частей одного кота; точки вращения (основание хвоста, шея) записываем в `design/README.md`.
- Базовые части — в оттенках серого, окрас задаётся в коде: цвет + отдельный слой узора (полоски, пятна, однотонный).
- Имена: `cat_<кот>_s<стадия>_<часть>.svg`, например `cat_fluffy_s2_tail.svg`.
- Единая толщина контура и ограниченная палитра.
- Исходники — в `design/`, готовые векторы — в `app/src/main/res/drawable/`.

**Чем помогает Ярик:**

- **Описания котов словами** — внешность, характер, чем отличаются силуэты. Из них Саня делает запросы к генератору.
- **Список всей нужной графики** — таблица: кот, стадии, эмоции, предметы магазина, цели, соседи, мошенник, фоны, значки. С пометкой, что нужно к 29.09, а что к финалу. Иначе что-то забудется.
- **Бесплатные ассеты** — ищет значки и фоны с лицензией CC0 или Apache 2.0 и записывает каждый в `design/licenses.md`.
- **Журнал ИИ-генераций** — следит, чтобы `design/ai-log.md` был заполнен: это пойдёт в документацию.
- **Простые предметы в векторе** — корм, мячик, кепка, когтеточка: это простые формы, их можно рисовать параллельно с котами. Файлы — через PR, как и контент.
- **Проверка различимости** — все 9 вариантов кота на каждой стадии в одной таблице: различаются ли они не только цветом.

**Бесплатные ассеты:** только с явной лицензией (CC0, Apache 2.0, OFL). Кандидаты: значки Material Symbols (Apache 2.0), наборы Kenney (CC0), шрифт Nunito (OFL). Каждый ассет записываем в `design/licenses.md`: что, откуда, лицензия, ссылка.

**Проба (Саня, до 21.09):** один кот × 3 стадии, разрезан на части, в Compose моргает и машет хвостом. Не получилось — решаем, что менять, сразу, а не 28.09.

## Kotlin для C#-разработчиков

- Официальный тур по Kotlin (kotlinlang.org → Docs → Kotlin tour) — 2–3 часа, почти всё знакомо по C#.
- Курс «Android Basics with Compose» (developer.android.com) — первые 3 раздела для Сани и Виталика.
- Соответствия: `class`/`data class` ≈ `class`/`record`; `val` ≈ `readonly`; `String?` ≈ nullable; корутины и `suspend` ≈ `async`/`await`; `map`/`filter` ≈ LINQ; `StateFlow` ≈ наблюдаемое свойство.
- Claude у Лехи и Виталика читает `CLAUDE.md` в корне — там правила проекта, чтобы код от двух Claude был в одном стиле.
