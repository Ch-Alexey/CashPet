## 1. Главная идея

```
Экран ──событие──► ViewModel ──Action──► GameStore ──► GameEngine.apply(state, action)
  ▲                                         │                    │
  └──── UiState ◄── map(GameState) ◄── StateFlow<GameState> ◄── Result: Ok(новое состояние, Feedback) | Rejected(причина)
                                            │
                                            └──► GameRepository.save(state)   (Room)
```

- **Всё состояние игры — один объект `GameState`.** Движок — чистые функции: получает состояние и действие, возвращает новое состояние и что изменилось. Никакого Android, никаких корутин, никакого времени — поэтому всё покрывается unit-тестами.
- **Один `GameStore` в `app`** держит `StateFlow<GameState?>` открытого профиля (`null` — онбординг), вызывает движок и сохраняет результат: сначала на диск, потом на экран. `dispatch(action)` возвращает `Result` — `Ok` с `Feedback` для панели «что изменилось» или `Rejected` с причиной; разовое событие для экрана из него делает ViewModel. Ещё `open(slot)`, `newGame`, `autoplay` (только демо), `delete(slot)`. ViewModel экранов только превращают `GameState` в свой `UiState` и отправляют действия. Владелец — Виталик, код — `app/.../app/store/GameStore.kt`.
- **Движок не знает текстов.** Он возвращает коды причин (`Rejection`, `FeedbackReason`), тексты — в `strings.xml` и JSON.
- **Демо и «Ускорить»** используют тот же движок: автопрогон — просто цепочка обычных действий.

## 4. API движка

```kotlin
class GameEngine(private val economy: EconomyConfig, private val catalog: Catalog) {
    fun newGame(profile: Profile, petName: String, look: PetLook): GameState   // неделя 1, стартовый бюджет
    fun apply(state: GameState, action: Action): Result

    // Только чтение — для экранов и предпросмотров
    fun weeksToGoal(state: GameState): Int?                                   // null — нет цели или нечего усреднять
    fun previewWithdraw(state: GameState, amount: Int): WithdrawPreview
    fun petMood(stats: PetStats): PetMood
    fun petReasonNow(stats: PetStats): PetReason                               // карточка кота; итог недели — WeekResult.petReason
    fun isTaskOpen(state: GameState, taskId: String): Boolean                  // unlock_week ≤ неделя или демо
}

sealed interface Result {
    data class Ok(val state: GameState, val feedback: Feedback) : Result
    data class Rejected(val reason: Rejection) : Result
}

sealed interface Action {
    data class SetPlan(val plan: Plan) : Action          // черновик в week.plan, переживает перезапуск
    data object ConfirmPlan : Action
    data class Buy(val itemId: String) : Action
    data class AddToWishlist(val itemId: String) : Action
    data class RemoveFromWishlist(val itemId: String) : Action
    data class ChooseGoal(val goalId: String) : Action
    data class Deposit(val amount: Int) : Action
    data class Withdraw(val amount: Int) : Action
    data object BuyGoal : Action                         // «Купить мечту»
    data class CompleteTask(val taskId: String, val outcome: Outcome) : Action   // монеты — только в первый раз
    data class DoJob(val jobId: String) : Action
    data object CloseWeek : Action                       // итог + падение показателей + новая неделя с карманными
    data class ChangeLook(val look: PetLook) : Action
}

sealed interface Rejection {
    data class NotEnoughMoney(val missing: Int, val options: List<Way>) : Rejection
    data class PlanExceedsBudget(val excess: Int) : Rejection
    data object PlanAlreadyConfirmed : Rejection
    data object PlanNotConfirmed : Rejection              // покупки и взносы — только после плана
    data class NotEnoughSavings(val missing: Int) : Rejection
    data object NoActiveGoal : Rejection
    data class GoalNotReached(val missing: Int) : Rejection
    data object GoalAlreadyBought : Rejection             // купленную мечту выбрать снова нельзя
    data object JobLimitReached : Rejection
    data object TaskClosed : Rejection
    data object InvalidAmount : Rejection                // ≤ 0 или не кратно 5
    data class UnknownId(val id: String) : Rejection     // товара, цели, задания или подработки нет в каталоге
}

enum class Way { DO_TASK, DO_JOB, CHEAPER_ITEM, WISHLIST, TAKE_FROM_SAVINGS }   // варианты «Что можно сделать?»

data class Feedback(
    val balanceBefore: Int, val balanceAfter: Int,
    val savingsBefore: Int, val savingsAfter: Int,
    val statChanges: Map<Stat, Int>,        // только ненулевые
    val reason: FeedbackReason,             // код для текста «почему»
    val weekResult: WeekResult? = null,     // только у CloseWeek
)

data class WithdrawPreview(val savedBefore: Int, val savedAfter: Int,
                           val weeksBefore: Int?, val weeksAfter: Int?)
```

**Правила, которые проверяет движок** (каждое — unit-тест):

- `SetPlan`: сумма ≤ `week.available`, все части ≥ 0 и кратны 5, иначе `PlanExceedsBudget` или `InvalidAmount`. После `ConfirmPlan` — `PlanAlreadyConfirmed`.
- `Buy`, `Deposit`: до подтверждения плана — `PlanNotConfirmed`. Цена > баланса — `NotEnoughMoney` с вариантами: `TAKE_FROM_SAVINGS` — только при покупке и только если копилки хватает (при нехватке на взнос не предлагается); `DO_TASK` — только если есть открытое непройденное задание; `DO_JOB` — только если лимит не исчерпан; `CHEAPER_ITEM` — если в той же части есть дешевле; `WISHLIST` — всегда.
- `Buy`: часть (`NEED` / `WANT`) берётся из каталога; эффект на показатели — не выше 100; товар «нужного» прибавляет `foodPoints` или `carePoints` недели.
- **Срок до цели:** ⌈осталось ÷ средний «отложено за неделю»⌉. Среднее — по последним 3 закрытым неделям, включая недели с нулём (так честнее: пропуски удлиняют срок). Если закрытых недель ещё нет — по «отложено» текущей недели. Среднее 0 — срок не показываем. `previewWithdraw` считает то же среднее с новым остатком.
- `ChooseGoal`: купленная мечта — `GoalAlreadyBought`.
- `Withdraw`: больше копилки — `NotEnoughSavings`. `BuyGoal`: без цели — `NoActiveGoal`, не хватает — `GoalNotReached`; списывает из копилки, кошелёк и факт «Нужно»/«Хочу» не трогает, `goalBought = true`.
- `CompleteTask`: закрытое задание — `TaskClosed`; повторное прохождение — `Ok` без монет.
- `DoJob`: больше `jobsPerWeek` за неделю — `JobLimitReached`.
- `CloseWeek`: всегда `Ok`. **Без подтверждённого плана M = 0** — иначе неделя без действий давала бы «План удался» и 30 очков; план считается 0 / 0 / 0. Экран «Завершить неделю» в этом случае сначала предлагает перейти к плану. Порядок: посчитать N, M, S и GP → стадия → падение показателей с минимумом 25 → `WeekResult` в историю → новая неделя: `available` = остаток кошелька + карманные.
- Баланс и копилка никогда не уходят в минус — проверяется тестом после любого действия.

## 5а. «Ускорить» — `core.sim`

```kotlin
interface Strategy {                                    // «разумная игра», «транжира», «скопидом»
    fun weekActions(state: GameState, engine: GameEngine): List<Action>   // действия одной недели, включая CloseWeek
}
object Autoplay {
    // Прогон недель до стадии [target], не больше [maxWeeks]; каждое действие — через engine.apply
    fun run(state: GameState, engine: GameEngine, strategy: Strategy, target: Stage, maxWeeks: Int = 6): List<Result.Ok>
    fun weeks(state: GameState, engine: GameEngine, strategy: Strategy, weeks: Int): List<GameState>  // ровно N недель — для симулятора
}
// Реализации: ReasonableStrategy, SpenderStrategy, SaverStrategy — сверены тестом с таблицами docs/02-экономика.md
```

«Разумная игра»: нужное = `needMin`; в копилку — половина свободного, **но не меньше `minSaveTarget`, если денег хватает** (иначе после недели транжиры откладывалось бы 5 и иконка «Копилка растёт» в демо горела наполовину); остальное — на желаемое в пределах плана. **Начатую неделю доигрывает:** если план уже подтверждён — берёт его; нужное, которое уже куплено, второй раз не покупает; желаемое и копилка — только на остаток плана. «Ускорить» можно нажать посреди недели.

Симулятор `:content:simulate` и тест-сторож баланса используют те же стратегии. Симулятор — в модуле `content`, а не `core`: он считает по настоящим JSON, а `core` о контенте не знает. Тест: из состояния после 1–2 ручных недель любого из трёх сценариев «разумная игра» доводит кота до Взрослого не больше чем за 4 недели. Владелец — Леха, демо-кнопку поверх него делает Виталик.

## 6. Хранение — `data`

**Предложение:** весь `GameState` хранится одной JSON-строкой в Room (kotlinx.serialization). Таблицы:

| Таблица | Поля | Зачем |
| --- | --- | --- |
| `game_state` | `slot` (CHILD / DEMO), `json`, `schema_version`, `updated_at` | Всё состояние игры одним снимком |
| `settings` | `sound`, `animations`, `seen_hints`, `demo_active` | Настройки, какие подсказки уже показаны, открыто ли демо |

**Совместимость сохранений:** `Json { ignoreUnknownKeys = true; encodeDefaults = true }`, у каждого поля `GameState` и вложенных в него классов — значение по умолчанию (у `WeekResult`, `Transaction`, `TaskRecord` их пока нет: **новое поле в них — только со значением по умолчанию**), `schema_version` растёт при несовместимых изменениях. Тест: сохранение из прошлой версии (файл-образец в `data/src/test`) читается без потерь. Потеря прогресса после обновления по ТЗ — блокирующая ошибка.

Почему так: одна таблица вместо десяти, нет миграций при каждом новом поле, сохранение — одна операция после каждого действия. ТЗ требует Room или SQLite — это Room.

**Таблицы меняются только с миграцией.** Версия базы 2: `settings.demo_active` (по умолчанию 0), `AutoMigration(1 → 2)` по схемам из `data/schemas`. Тест `DatabaseMigrationTest` открывает базу версии 1, собранную ровно по `1.json`, и проверяет, что профиль и настройки на месте.

Тесты-сторожа — раздел «Тесты-сторожа» в [07](07-формат-заданий.md) плюс: каждая цена кратна 5; у каждого товара `part`; в `texts.json` фраза для каждой причины; `economy.json` проходит неравенства раздела 19 (кроме 6 — непредвиденный расход после 29.09) и три сценария через стратегии `core.sim`.
